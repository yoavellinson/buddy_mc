# Conditional EDM-based Binaural-to-Mono Dereverberation

## Goal

Train a conditional EDM diffusion model that receives:
- binaural reverberant speech `[B,2,T]`

and predicts:
- clean anechoic mono speech `[B,1,T]`

Main use case:
- dereverberation / speech enhancement
- preserve speech content while removing room reverberation and additive artifacts

---

# Core Architecture

- EDM diffusion model (Karras/EDM style)
- conditional generation
- network input:
  - noisy latent `x_t`
  - condition `cond` (binaural reverberant speech)
- output:
  - predicted clean mono waveform

Current status:

# Important Alignment Bug Fixed

Previously:
- reverberant signal length = `L_wav + L_rir - 1`
- target length = `L_wav`
- crops were misaligned

Now fixed by:

```python
if L_rir > L_clean:
    data = np.pad(data, (0, L_rir - L_clean))
elif L_clean > L_rir:
    data = data[:L_rir]
```

before shared cropping.

This fix significantly improved training.

---

# Critical Binaural Averaging Bug

NEVER average binaural channels:

```python
mono = y.mean(dim=1)
```

This causes:
- comb filtering
- doubled speech
- overlap artifacts
- because of interaural delays

Use single channel instead:

```python
mono = y[:, :1, :]
```

This bug existed in:
- warm initialization
- WPE init
- debug listening

NOT in the actual training target.

# Important Likelihood Observations

Using:

```yaml
lambda_sisdr = 0
lambda_stft > 0
```

produces reverberant outputs.

Interpretation:
- STFT likelihood preserves reverberant structure
- SI-SDR is essential for dereverberation

Therefore:
- SI-SDR must dominate
- STFT only small stabilizer

# STFT Loss Issue Found

Original STFT implementation used:

```python
loss = torch.mean(torch.sum(diff2, dim=-2))
```

My replacement incorrectly used:

```python
loss = torch.mean(diff2)
```

This weakened gradients significantly.

Correct implementation:

```python
loss = torch.mean(torch.sum(diff2, dim=-2))
```

After fixing:
- noise improved
- denoising improved

# Things Already Tested

## Magnitude Scaling Constraint

Previously:

```python
x_den = x_den * (0.05 / x_den.std())
```

inside sampling loop.

This often degraded sound.

Now:
- removed from prior score computation
- outputs sound better without scaling

Conclusion:
- model already learns proper scale
- forced scaling hurts dynamics
